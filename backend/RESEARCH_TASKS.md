# 三个科研任务：实现和验收

代码已提供三个任务所需的白名单计算和表图契约。真实数据可用性必须由服务器工具运行证明；不能把本地测试或工具注册称为任务全部上线。沿用 LangGraph 有界规划、执行、证据校验和再规划；分析算法在分析层，MCP为薄接口，前端只渲染。无需新数据库、R运行时或分布式组件，无数据库迁移。

## 科学口径

| 任务 | 工具 | 要求的最终产物 |
| --- | --- | --- |
| 群落与环境 | `community_analysis` | V4/V9分开的表层全球分布、Surface/DCM丰度与exp(Shannon)纬度图及Shannon数值；Spearman、p/BH q与有效样本数、两成分PLS；四粒径分布、Bray–Curtis、NMDS坐标/Stress1/收敛与环境拟合 |
| 功能谱与MetaG/MetaT | `function_study`；有明确DNA/RNA一致性统计要求时组合 `compare_function_signals` | 合并Top100贡献、粒径/海区分配，DUF285及LHC总体/亚家族信号、PLS图表；要求序列时调用已准备序列工具 |
| 单功能与温度 | `function_environment` | 每个已映射PANGAEA样本一行的温度和目标Pfam MetaT信号、Spearman及散点图 |

群落工具的 `markers/taxon/sample_ids/depths/outputs/environment_variables` 可选择科研范围，不能为得到完整状态而删去受阻目标。ASV总reads≥3、至少2个原样本检出条件在所选样本内分别按标记重算；分子为过滤后目标ASV，分母为过滤前全部真核ASV。先逐原样本计算Shannon和exp(Shannon)，再平均技术重复和等价粒径；零目标库的多样性为空，并明确不同于作者vegan零库约定。四粒径排序前再按站位、水层、粒径等权汇总，完整四粒径及非零分布才进入NMDS，不补齐未采集粒径。

默认 `environment_source=paper` 使用固定作者提交的站位/水层环境资料。`context_stat` 可明确选择，但变量范围不同，不能将硝酸盐+亚硝酸盐当作硝酸盐。默认资料没有盐度；显式请求 `Salinity`/`salinity` 时须另有带单位和来源的补充表，否则受阻。作者环境资料中的铁及部分氮变量来自模型，单位未确认时保留不确定性。`abslat`从采样纬度取绝对值。

Spearman双侧置换检验、envfit置换及BH校正均返回实际样本数、种子、置换次数和缺失排除。PLS为标准化两成分描述性模型，不提供因果、预测效果或显著性结论。未验证观测独立性时置换p值只供探索，不应作为确认性检验。NMDS使用多起点单调SMACOF、Bray–Curtis和Stress1；无vegan自动转换，强相等秩处理，与作者 `metaMDS` 不保证相同坐标或stress。V4/V9分开建模，区别于作者部分图中汇集标记指标的做法，不能声称逐值复现。单次NMDS最多500组，可明确缩小范围。

功能榜单默认 `normalization=taxon_total`，全部已提供硅藻基因信号（含未注释）为分母，合并后采样组等权平均，不再归一化为保留功能100%。作者脚本份额仅在显式 `author_script` 模式提供；作者公开Pfam汇总表缺全部基因分母，不能选择 `taxon_total`。共享基因与多结构域不分摊。原论文参考贡献列始终为作者口径，不能直接与当前总基因口径比较百分比。

跨类任务默认 `signal=provided_sum`，汇总目标基因的已提供MetaT值；单位不擅自推断。`relative`为明确选择的样本内全部类群基因信号份额。显式映射到同一PANGAEA样本的记录合并分子/分母，只贡献一行统计观测，不能把技术记录当作独立样本。缺家族记录不当生物学零，未映射范围和覆盖率明确报告。

### 官方样本与环境补充（2026-10-07）

MATOU 2018 Supplementary Data 8（DOI:10.1038/s41467-017-02342-1）提供实验、Sample Code与Tara条码的直接关系。Science 2022 Table S4（DOI:10.1126/science.abm5847）可通过ENA精确运行号关联极地样本；同一运行号对应多个条码时必须保留冲突，不能根据站位或相似名称择一。

当前581个MetaT样本中，原映射423个；新增134个经ENA和Table S4唯一核验的极地样本，另17个在原论文已核实身份但不在当前核心背景表，其温度可由PANGAEA.875576按确切条码补充。上述参考资料接入后最多574个有核验映射，不等于574个均有完整功能信号。6个补充表运行号冲突及`80DCM1GGMM14`仍未解决，不宣称581个完整支持。极地新增134个包含117个TruSeq及17个SMARTer建库样本；映射证据保留方法，汇总相关仅作探索，应使用明确的`sample_names`按方法分层核验，不能归因为纯环境驱动。

`research-context-v2`新增可选`sample_environment`长表，列为`sample_id_pangaea, variable, value, unit, evidence, method, context_details`（TSV）。唯一键为确切样本ID和变量；值须有限或缺失，证据、方法、单位和上下文说明非空。来源版本、源及产物摘要固定在同一研究清单；继续兼容v1。映射目标允许存在于核心表或该补充表；查询只补充缺失环境值，不替换核心有效值，单位未经一致性核验时拒绝混算。温度单位明确为`degree_Celsius`；其他变量须已有同名单位声明。逐点返回补充来源、证据、方法和上下文，使用补充值时增加警告及来源节点。资料包只读、需离线准备，不开放模型任意读取路径。

离线准备时可添加`--sample-environment <补充.tsv> --sample-environment-source <来源> --sample-environment-version <源版本>`。PANGAEA温度采用环境特征Q2中位数，原始方法允许距离间隔小于100 km、时间间隔小于2天；必须保留逐样本间隔、观测数和传感器文件，不能称作同步水样实测。与当前核心表可比较的1420个温度值已逐值一致核验，17个新增条码、BioSamples、ENA编号也逐项一致。无需新服务或数据库，已有研究包出现/变化仍要求重启两端。

## 服务器准备与升级

服务器仍保留九份原始数据和现有派生产物。新研究资料包为派生/参考资料，不能当作第十份已接入原始科学数据。同步本版本 `src/tara_agent/`、`pyproject.toml`、`uv.lock` 和相关 `deploy/` 脚本到现有服务器代码目录；`uv sync --locked` 后准备资料，再用现有启动方式重启科学服务及本地后端。保留端口、凭据和原数据路径。单机Docker升级沿用现有构建启动命令；远程模式仍走原隧道。

任务一论文环境资料可由固定作者提交下载，无需重新处理18S或MATOU：

```bash
uv run python deploy/prepare_research_context.py --processed-dir <核心派生目录> --output-dir <核心派生目录>/research --download-paper-environment --download-dir <尚不存在的作者环境下载目录>
```

原始输入只读，输出目录须不存在，清单最后发布。环境表缺失只阻断关联/环境拟合，分布、多样性和可计算的NMDS坐标仍保留；全任务状态保持部分完成。

任务三不能仅靠九个文件中的站位、水层和粒径编码证明同一物理样本。须提供来源可审核的TSV：

```text
assay	sample_name	sample_id_pangaea	evidence
```

每行是原始MATOU实验及样本名、确切PANGAEA编号、样本登记/批次证据；同一实验样本只能指向一个PANGAEA样本。`evidence`不能只写“站位粒径相同”。来源和版本另用参数记录。脚本验证两端ID存在、唯一键、空值、源文件摘要、核心生成代和MATOU清单；该校验不能替代人工/权威资料对样本身份的科学核验。没有映射时工具明确返回 `blocked`。

有映射时在首次准备命令中加入：

```bash
--sample-mapping <经核验映射.tsv> --mapping-source <登记表来源> --mapping-version <版本> --matou-dir <MATOU派生目录>
```

已有研究包不可覆盖。需要新增映射时，先用独立新目录同时准备环境表和映射，核验后在服务停止期间备份旧 `research` 目录，再将新目录移至 `<核心派生目录>/research`，重启两端。备份研究目录、原始映射及其证据即可恢复；资料包故障只阻断依赖分析，版本漂移使服务要求重启。资料很小，沿用现有磁盘，无新增常驻资源。

任务二继续使用已经准备的 `<MATOU派生目录>/paper_task2` 与功能缓存；当前LHC亚家族缺缓存时，按后端README的固定作者资料准备命令离线生成，不用总体LHC冒充亚家族。

同步后，在本机 `backend/`、原SSH隧道有效时运行独立验收：

```powershell
.venv/Scripts/python.exe deploy/check_remote_research_tasks.py --output-dir <尚不存在的验收目录>
```

报告分别列三个任务状态；`partial/blocked`不算三个任务全通过。完整JSON保存数据、图表规格及同树来源节点。随后通过认证会话分别提出三类问题，并核对刷新后的表图、标签、来源、条件继承和Trace树；独立工具验收不能替代真实模型/网页验收。代码变化导致旧科学服务拒绝调用是预期保护，不应关闭版本检查。

## 会话输出

NMDS默认20个固定种子起点、每个起点最多1000次迭代，收敛容差保持1e-7。`nmds_max_iterations`可明确设置100至5000；预算耗尽仍返回未收敛状态，不能放宽收敛标准或删减样本以取得完成标签。结果记录实际迭代、预算和容差。真实V9验收数据的最佳起点需306次才收敛，旧300次预算不足；增加预算不保证其他问题必然收敛。

最终回复由应用加 `【最终结果】`；部分完成加 `【最终结果（部分完成）】`。表图根据 `result_role` 和 `artifact_roles` 标注 `【中间步骤结果】` 或 `【最终结果】`，刷新后从持久化响应恢复。多步骤规划的 `final_result_steps` 与用于证明目标的 `evidence_steps` 分开：只有用户直接要求的产物才标最终，检索和准备不因成为证据而变成最终产物。完整计算明细保留供审核和导出，回答不重复大表或输出未请求的序列。
